# WHY THIS FILE EXISTS SEPARATELY FROM requirements-docker.txt:
# the backend service (session/index CRUD, auth, chat routing) never
# directly imports torch/transformers/docling/etc - those are only used

# processing and embedding. Before this split, both services shared one
# requirements file that included the full multi-GB ML stack, meaning
# the lightweight backend image was needlessly bloated by everything the
# heavy rag-api image needed. This keeps the backend image small and the
# build fast.
